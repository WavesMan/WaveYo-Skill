# 最小开发闭环

> 新需求先验证**最小业务语义**，优先复用项目已有的真实依赖；不是先搭建新基础设施。
> 2026-10-27 确认的取舍：开发验证用项目已有的真实数据库，隔离单测（内存库 / SQLite / mock）保留在单测层。

---

## 1. 开发基线

```text
需求 → ① 已有真实数据库 + 简单 HTTP / 进程内缓存
           ↓ 验证领域模型、事务与接口契约
       ② 按任务需要接入已有 Redis / 对象存储等真实依赖
           ↓ 验证并发、一致性和实际错误
       ③ 有证据时才增加分布式能力（分片、副本、消息系统）
```

- 隔离单测（内存库 / SQLite / mock）只用于**无需外部服务**的单元验证、故障注入与兼容性回归，
  不是端到端验证的替代品。
- **不能**因为真实数据库连不上就回退到内存库，再报告「开发验证通过」。
- 也**不要求**把所有隔离单测迁移为外部数据库测试——两层各司其职。

---

## 2. 配置来源

- 加载顺序与启动入口一致：默认值 → 基础配置 → 本地覆盖文件（后者覆盖同名字段）。
- 真实数据库与连接池参数从项目**已有的本地配置**读取；不为验证另写一份开发专用 DSN。
- 本地覆盖文件不入库。
- **不得输出**配置文件全文、DSN、密码、Token、AK/SK，以及带配置内容的解析错误（含连接串）。
- 本地配置缺失、非法或连接失败时**明确失败**，不静默回退到内存库或内置默认值。

---

## 3. 最小验证入口

用项目**已有的集成测试入口**（构建标签、环境变量开关、专用 test 命令均可），
在真实数据库的**隔离 schema** 上执行与线上同形态的断言：

1. 先核对当前连接指向的 schema，再在其中建表。
2. 结束后关闭验证连接、精确删除本轮 schema，并确认已不存在。
3. **不迁移、不清空业务 schema**；不需要额外的缓存或存储凭证。
4. 命令示例（占位，按项目替换）：

```bash
# 打开集成测试开关，只跑一条最小闭环用例
<ENV_SWITCH>=1 go test ./internal/... -tags=integration -run '^TestMinimalLoop$' -count=1 -v
```

新领域仍按项目既有的模型与骨架生成方式实现，再在同样的隔离环境验证其最小业务闭环。
**现有入口是可执行范例，不代表新领域无需自己的断言。**

常规回归：

```bash
go build ./...
go vet ./...
go test ./... -short
```

短测试与 CI 可以保留隔离单测。它们与真实数据库开发验证**互补**，
不能用「短测试通过」代替行锁、时钟、序列、类型与事务语义的验证。

---

## 4. 不提前增加的能力

| 当前最小需求 | 首选实现 | 升级条件 |
|---|---|---|
| 持久化及事务 | 项目已配置的单库数据库 | 已有连接直接复用，不另建数据库服务 |
| 简单缓存 | 进程内缓存或已有领域缓存 | 有实际瓶颈证据才增加新缓存层 |
| 简单副作用（通知、导出） | 直接调用已有端口 / 同步执行 | 有持久化或重试需求才引入队列 |
| 单实例互斥 | 数据库行锁或已有同步机制 | 多实例竞争有证据才增加分布式锁 |
| 部署 | 本地运行 / 已有启动脚本 | 任务明确要求才上容器编排或多实例 |

不修改项目框架或代码生成产物；不以切换数据库为由提前建设分库、主从、缓存集群或消息系统。

---

## 5. 交付要求

- 写清最小业务语义、配置来源、真实数据库的验证命令。
- 记录实际通过/失败、驱动类别、隔离清理结果；**失败不能**通过删除断言、加无理由 skip
  或换内存库掩盖。
- 数据库时钟、序列、隔离级别或 SQL 方言差异必须调查根因；行为修复与验证重构**分别提交**。
- 历史验证记录保留原事实；新增的验证记录不得冒充「过去已经执行」。
- 明确说明**未验证**的部分：缓存、对象存储、生产迁移、容量范围。
  不把单库 HTTP 验证写成「完整生产验收」。
