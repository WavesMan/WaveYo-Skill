# 前端 UI/UX 设计要求

> 触发时机：新建或修改前端页面、导航与菜单、表单、列表、Dialog、主题与配色、
> 交互反馈、异步加载、响应式布局，或做视觉验收时必读。
>
> 本专题只管**界面层**：结构、视觉、交互、状态反馈、可访问性。
> 权限模型、存储与事务、令牌保管、接口鉴权、Git 流程不在此文档，见对应专题。

---

## 1. 用途与触发条件

### 用途

让界面在**真实使用条件下**可用：能直达、能返回、能等、能看清、能只靠键盘操作。
不是做「截图好看」的页面，而是做「反复用不出错」的界面。

### 触发条件（命中任一条即适用）

- 新增页面、路由、二级详情页、看板、列表页
- 改动导航、菜单、标签页、面包屑、返回栏、吸顶操作区
- 改动表单、筛选器、日期选择、分页、选择器（Select / Dropdown）
- 改动 Dialog / Drawer / Popover / Tooltip / Toast 等浮层
- 接入或改造异步加载、骨架屏、空状态、错误重试
- 调整主题、配色、字号字重、间距、动效
- 做视觉验收、走查、截图评审

### 不触发

纯后端接口实现、纯数据迁移、纯 CI 配置、纯文档改写（除非文档本身就是页面）。

## 2. 适用边界

| 属于本专题 | 不属于本专题（转交对应专题） |
|---|---|
| 页面层级与导航结构 | 对象存储权限、预签名 URL 策略 → 项目存储文档 |
| 视觉层级、留白、配色、字重 | 数据库事务与隔离级别 → 数据层文档 |
| 交互状态：加载 / 空 / 错 / 成功 / 冷却 | 令牌存储位置与刷新策略 → 认证文档 |
| 浮层行为、焦点管理、键盘可达 | 接口授权与越权校验 → 后端错误边界 |
| 筛选、分页、日期范围表达 | 分支、提交、PR → `git-workflow.md` |
| 动效与降级（reduced-motion） | 上游错误分类与公开映射 → `upstream-error-handling.md` |

**一条硬边界**：不能因为「顺手」把后端约束写进 UI 规范，也不能因为「前端好做」把鉴权判断搬到前端。
界面的职责是**如实表达状态**，不是替后端做安全决策。

## 3. 核心规则

### 3.1 页面与布局

- **复杂业务详情优先独立二级页**，具备可直达 URL，支持刷新、前进后退、深链接、返回上一级。
  详情页塞进 Dialog 会带来三个必然问题：无法直达、刷新丢状态、返回键行为不可预期。
- **不大量堆叠 Card**。卡片是「并列的同类单元」容器；页面的层级靠标题、留白、分隔表达，
  不靠一层层卡片套卡片。
- **不用大型 Dialog 承载完整业务页面**。Dialog 只用于短流程：创建、确认、裁剪、批量改属性。
  判断标准：这个流程需要滚动超过一屏、或需要来回查资料 → 它应该是页面。
- **管理界面层级清晰**：导航 → 标题与操作 → 筛选 → 列表/表格 → 分页。
  每一层之间留有可辨的间距，不要让筛选项贴在标题上、按钮挤在表格边线里。
- **合理留白**。顶部区域、说明文字、主操作按钮之间保持节奏；密集不等于专业，拥挤只会让人点错。
- **长名称、日期、筛选框宽度适中**：默认宽度按内容常见长度定，超长文本截断（ellipsis）并支持完整查看
  （title 属性、悬浮提示或详情页）。不允许「宽度随内容无限撑开导致布局抖动」。

### 3.2 菜单与选择器

判据一句话：**Select 用于选择，Dropdown 是命令集合。**

| 控件 | 语义 | 选中后 |
|---|---|---|
| 操作菜单（Dropdown / Menu） | 一组命令 | 立即执行，或进入确认/二级流程 |
| 数据选择器（Select / Combobox） | 录入一个值 | 回显到控件内，等待保存或触发查询 |

- **数据选择器必须具有外边框**，有明确的可点击区域、选中回显、清空方式，值在未提交前属于「待保存」状态。
  去掉边框做成「看起来像纯文本」的选择器，用户无法判断这是可编辑字段还是只读展示。
- **2 个选项禁止折叠下拉**：
  - 互斥值（如「启用 / 停用」中的状态枚举）→ 单选按钮或分段控件（Segmented Control）
  - 布尔状态 → 开关（Switch）
  - 两个独立命令 → 两个直接平铺的按钮
  为两个选项点开一个下拉，是纯损耗。
- **少于 5 个选项直接平铺**（单选组、标签组、分段控件均可）。
- **超过 10 项必须限高并提供搜索**。限高建议 264px 左右（约 6～8 行），超出滚动；
  选项多到需要滚动却没有搜索框，等于让人肉眼扫描。
- **大量数据采用合适的搜索交互**：远程搜索需防抖、显示加载与「无匹配」；熟悉格式的值（日期、编号、手机号）
  允许直接输入，不必强制点选。
- **统一主题**：自定义控件与原生控件视觉一致。浏览器原生 `select`、`input[type=date]` 与设计系统混用会出现
  明显色差、圆角与高度错位，必须统一或明确替换为受控组件。

### 3.3 导航与浮层

- **当前选中项来自响应式路由状态**（路由参数 / location），不来自「点击时设置的局部变量」。
  手工维护高亮状态的组件，刷新和深链接必然错位。
- **点击、刷新、前进后退、深链接**四种入口下，高亮项与内容必须一致。
- **重复点击当前项不产生无意义跳动**：不重新走一遍全屏加载、不重置滚动位置、不闪一下骨架屏。
- **Tooltip 悬停显示、离开关闭，导航后立即关闭**。禁止「第一次点击显示、第二次点击才消失」的交互。
- **保留键盘焦点、Escape 关闭、触摸可用性**：浮层打开时焦点进入浮层，关闭后回到触发元素；
  触摸设备没有 hover，必须有可点开的等价入口。
- **不用全局 `blur` 或关闭可访问性来掩盖浮层残留**。浮层关不掉是状态管理问题，
  用 `onBlur` 粗暴隐藏会顺手把键盘用户挡在门外。

### 3.4 返回与吸顶

- **真实详情页的返回与主要操作持续吸顶**。滚动到任何位置，用户都能回到列表、都能看到主操作。
- **按实际滚动容器计算位置**，不硬编码某个项目的类名或头部高度。
  多滚动容器场景（页面滚动 + 内部表格滚动）先确认真正滚动的是谁。
- **不遮挡正文、锚点跳转目标及键盘焦点**。吸顶高度要参与 `scroll-margin-top` 或等效补偿。
- **层级低于 Dialog 和其他必要浮层**：吸顶条不能盖住弹窗、下拉、Toast。
- **返回列表恢复筛选、页码和阅读位置**。这是详情页存在的前提：进得去还要回得来。
  实现上优先用 URL 承载状态（query 参数），而不是内存变量。
- **直接进入详情时有合理默认上级**：从外部深链接打开时，返回按钮要有确定的落地页（如列表首页），
  不能变成「返回浏览器上一页」的随机跳转。
- **中心根级页面优先使用清晰导航，不机械添加返回栏**。首页、一级模块首页没有「上一级」，
  硬加返回栏只是噪音。

### 3.5 异步与状态

- **避免闪现「加载中」、空状态或整块正文消失**。请求前 100～200ms 内的闪烁，比多等一会儿更伤可用性。
- **保持应用壳、导航、标题与操作位置稳定**：加载中不改变布局，加载完成也不跳动。
- **首次加载使用匹配布局的局部骨架**（宽度、行数、列数接近真实内容），不要整页 spinner。
- **已有内容刷新时保留可用正文**：后台刷新、轮询、切换页签时不把已读内容清空。
- **快速切换不串页**：请求要能取消或按 key 丢弃过期响应，避免 A 页数据写进 B 页。
- **错误提供局部重试**，不必整页刷新；重试后原筛选与滚动位置保持不变。
- **空状态只在确认结果为空后展示**：请求失败不等于空，加载中不等于空。
  三种状态（loading / empty / error）视觉与文案必须可区分。
- **不靠全屏淡出或人为延迟掩盖请求问题**：加一层 500ms 的过渡动画不会让接口变快。

### 3.6 筛选、日历与分页

- **常用筛选外置**，不常用收起；不要把所有条件都塞进「高级筛选」面板里。
- **需要统一查询时，条件编辑后点击「查询」**；即时生效与按钮触发不能混在同一组条件里
  （一半即时、一半要按钮，用户无法预测）。
- **聚合选择用简洁标签表达**（如「地区：华东 +2」），不铺开大量子项。
- **通用日历可复用**；快捷日期（今天 / 近 7 天 / 本月）在日历内以紧凑小按钮平铺，不额外开一层弹窗。
- **明确范围起止、时区、超限项置灰**。跨时区场景必须显示基准时区，避免「差一天」类争论。
- **输入宽度适当，支持直接输入及合法清空**：日期框宽度按 `YYYY-MM-DD` 或 `YYYY-MM-DD HH:mm` 定，
  不按容器自适应拉满。
- **长列表顶部提供条数选项（10/20/50/100）**，必要时上下均有分页；列表很长时只留底部分页会让人先滚到底。
- **看板下钻范围清晰**：点某个数字进去，落到列表的筛选条件必须与该数字口径一致。
- **导出入口与当前上下文一致**：导出的就是屏幕上这份数据的口径，导出前在文案里说清范围与数量。

### 3.7 操作反馈

- **主要少量命令直接平铺**（1～3 个），不要藏进「更多」菜单。
- **禁用、加载、失败和成功状态明确**：同一按钮的四种状态文案或图标可区分，不靠颜色深浅暗示。
- **危险操作确认，失败保留上下文，防止重复提交**：删除失败后表单内容不能清空；提交中禁用并显示进度。
- **状态提示不能只依赖颜色**：同时用图标 / 文案 / 形状区分成功与失败（色觉差异用户）。
- **验证、发码、导出等连续流程避免「重复点击才能启动」**：首次点击无响应是最常见的信任损伤。
- **按钮在初始、加载、重试及成功状态保持稳定尺寸**：文案变化（「提交」→「提交中…」→「重试」）
  不能让按钮宽度跳动，用固定最小宽度或骨架占位。
- **冷却与等待时间明确显示**：倒计时标注秒数，区分「成功」「失败」「被限流」三种语义，
  不要把限流提示写成「操作失败，请重试」（会诱发连续重试）。

### 3.8 视觉与动效十条

1. **普通表面靠约 1%～3% 的微明度差分层次，减少边框，禁止纯黑 `#000`**。
   浅色参考：`#f5f5f3`（页面底） / `#fcfcfb`（卡片面）；
   暗色参考：`#0b0b0a` / `#151515` / `#1a1a19` / `#20201e`。
   **输入框的明确边界不受「去边框」影响**：可选择项、可输入项必须有可辨轮廓。
2. **输入框聚焦用加深的双环 `box-shadow`**；若改用 `outline: none`，必须另留清晰的键盘焦点样式，
   绝不允许「聚焦无任何视觉反馈」。
3. **暗色模式字重约降低 40**（例如 400 → 360）；字体不支持可变字重时提供回退（换字族或直接不降），
   不得为了字重牺牲层次与可读性。
4. **短文字流式出现**：单字 90ms，`blur(6px)` → 清晰，缓动 `cubic-bezier(.215,.61,.355,1)`，
   相邻字错开 30ms。**不用于整页正文、导航及表格的反复播放**（重渲染会反复触发，变成闪烁噪音）。
5. **行内图标 `vertical-align: -0.125em`**；Flex 布局中按实际（`align-items` + 图标容器）对齐，
   不靠负 margin 硬掰。
6. **时间、计数、分页使用 `tabular-nums`**，避免数字变化时列宽跳动。
7. **折叠优先 `grid-template-rows: 0fr → 1fr`**，不写 JS 逐帧计算高度。
8. **正文 `text-wrap: pretty`**，作为渐进增强；不支持的环境保持默认换行，不影响可读性。
9. **拖拽收尾用弹簧参数 1200 / 80（stiffness / damping），点赞或对勾用 380 / 18**。
   这些数值依赖具体动画引擎（如 react-spring / Framer Motion 的 stiffness + damping），
   **不要把 CSS `easing` 当作物理弹簧**：CSS 缓动没有质量与刚度概念，参数名也不能混用。
10. **复制成功对勾 2.5s 后淡出恢复**；连续复制时**更新计时**而不是叠加多个定时器（否则第二次复制会提前消失）。

**补充要求**

- **文本选中使用清晰高亮**，选中背景与文字仍有足够对比（自定义 `::selection` 时最容易把文字弄成白底白字）。
- **动效不阻塞操作，不新增无业务价值的动画**。动画服务于「状态变化可感知」，不是装饰。
- **支持 `prefers-reduced-motion: reduce`**：流式出现、位移、弹簧回弹降级为直接切换或纯透明度过渡。
- **桌面、窄屏、长文本、键盘操作、200% 缩放均可用**：200% 缩放下不允许出现被裁切的按钮、重叠的表单。
- **闪屏与交互过程用录屏或连续帧验收**；静态截图不能证明交互正常（截图看不出闪烁、跳动、二次点击问题）。

> 以上视觉条目是**默认基线**，不是审美裁决。项目已有设计系统时以其令牌（颜色、间距、字重、动效曲线）为准，
> 但「禁止纯黑」「焦点可见」「状态不只靠颜色」「reduced-motion 降级」四条不接受覆盖。

## 4. 实施方法（调查 → 设计 → 实现 → 动态验收）

### 4.1 调查

1. 读现有设计令牌与组件库：色板、间距、圆角、字阶、动效变量，确认可复用什么。
2. 读现有页面骨架：应用壳、导航、面包屑、吸顶条、Dialog 容器是谁提供的。
3. 确认路由方案：状态放在 URL 还是内存？深链接是否已有先例。
4. 确认数据加载方式：是否有全局请求封装、是否有缓存层、是否支持取消。
5. 找出**同类页面 1～2 个**作为参照，避免自创一套层级。

### 4.2 设计

1. 先定**信息层级**：页面 → 区块 → 控件，写成三层清单，再谈样式。
2. 定**状态矩阵**：每个数据区块列出 loading / empty / error / partial / success 五种展示。
3. 定**交互契约**：点击后发生什么、失败后停在哪、返回时恢复什么。
4. 定**控件类型**：按 §3.2 判据选 Select / Segmented / Switch / 直接按钮，不凭习惯。
5. 需要新增组件时，先问：能否用现有组件 + 少量样式实现？不能再新建。

### 4.3 实现

- 状态与展示分离：请求状态（idle/loading/success/error）由数据层统一表达，组件只渲染。
- 列表 key 稳定，不用数组下标；避免重排导致输入框失焦。
- 骨架屏尺寸跟随真实内容容器，不用固定高度硬撑。
- 焦点管理显式写：打开浮层 → 移入；关闭 → 归还；路由切换 → 移到主标题或首焦点。
- 动效参数集中为令牌，不在组件里散落魔法数字。

### 4.4 动态验收（必做）

| 验收方式 | 覆盖问题 |
|---|---|
| 录屏（推荐 15～30s） | 闪烁、跳动、二次点击、浮层残留 |
| 连续帧 / 截图序列 | 骨架到内容的过渡是否稳定 |
| 键盘走查 | Tab 顺序、Escape、焦点归还、跳过导航 |
| 200% 缩放 + 窄屏 | 裁切、重叠、横向滚动条 |
| 弱网 / 慢接口（DevTools 限速） | 加载态与空态是否可区分 |

> 只给一张静态截图的「已验收」，在 UI 任务里不算验收完成。

## 5. 常见错误

| 现象 | 根因 | 修正 |
|---|---|---|
| 详情放进 Dialog，刷新就丢 | 用弹窗承载页面级状态 | 独立二级页 + URL 状态 |
| 进详情能进、返回丢失筛选 | 筛选状态存在组件内存里 | 状态进 query，返回读 URL |
| 两个选项还开下拉 | 按「字段多少」选控件 | 互斥用分段/单选，布尔用开关 |
| 20 个选项平铺一屏 | 未设限高与搜索 | 限高 + 搜索框 |
| 下拉菜单被当成表单字段 | 命令与选择语义混淆 | 命令用 Menu，录入用 Select |
| 刷新后高亮错位 | 高亮状态由点击事件维护 | 从路由派生 |
| Tooltip 要点两次才关 | 用点击 toggle 实现 hover 语义 | hover/focus 显示，离开/Escape 关闭 |
| 加载时整块正文消失 | 用 `v-if` 切换整个区块 | 保留壳与旧内容，局部骨架/局部遮罩 |
| 空状态出现在请求失败时 | 未区分 empty 与 error | 三态分离，错误给重试 |
| 快速切换页签串数据 | 未取消或未校验过期响应 | 请求取消或按 key 丢弃 |
| 按钮宽度随文案跳动 | 省略了最小宽度 | 固定尺寸或占位 |
| 只靠颜色区分成功/失败 | 视觉反馈单一 | 加图标与文案 |
| 200% 缩放按钮被裁 | 固定像素高度 + 无换行 | 用相对单位与弹性布局 |
| 暗色模式正文刺眼 | 未降字重、用纯黑底 | 参考 §3.8 色值与字重 |
| 动效无法关闭 | 未接 reduced-motion | 媒体查询降级为直接切换 |
| 吸顶条盖住弹窗 | 层级/z-index 未规划 | 吸顶层低于 Dialog |

## 6. 验收清单

**结构与导航**

- [ ] 复杂详情是独立页面，可直达、可刷新、可返回
- [ ] 返回列表后筛选、页码、阅读位置已恢复
- [ ] 深链接进入详情时，返回目标确定且合理
- [ ] 导航高亮来自路由状态；刷新与前进后退后仍正确
- [ ] 重复点击当前导航项无加载闪烁与位置重置

**控件**

- [ ] 选择器有外边框、有回显、有清空方式
- [ ] 2 个选项未使用下拉；少于 5 个选项已平铺
- [ ] 超过 10 项的列表已限高并支持搜索
- [ ] 命令菜单与数据选择器语义未混淆
- [ ] 自定义控件与原生控件视觉统一

**状态**

- [ ] loading / empty / error / success 四态可区分
- [ ] 刷新时保留已有内容，未整块清空
- [ ] 快速切换无串页；过期响应未渲染
- [ ] 错误有局部重试，重试后上下文不丢
- [ ] 提交中禁用、失败保留输入、成功有明确反馈

**视觉与可访问性**

- [ ] 未使用纯黑背景；表面分层靠微明度差
- [ ] 输入框有明确边界，聚焦有可见焦点（含键盘）
- [ ] 状态提示不只依赖颜色
- [ ] 时间/计数使用 `tabular-nums`，数字变化不抖动
- [ ] `prefers-reduced-motion` 已生效
- [ ] 键盘可完成主流程：Tab 顺序、Escape、焦点归还
- [ ] 200% 缩放与窄屏无裁切、无重叠、无横向滚动
- [ ] 长文本与长名称截断正确，完整内容可查看

**验收证据**

- [ ] 已提供录屏或连续帧，而非单张静态截图
- [ ] 已用弱网/慢接口验证加载与空态
- [ ] 已记录未验证项（如未测试的浏览器、未覆盖的分支）

## 7. 示例（中性场景）

> 以下为通用示意，**按实际业务选用**，不构成任何具体产品信息架构的强制要求。

**示例一：订单详情**

- ❌ 在订单列表里点「查看」弹出一个 1200px 宽的 Dialog，内嵌 5 个 Tab。
- ✅ 跳转 `/orders/:id`：顶部吸顶「返回列表 + 状态 + 主操作」，正文分「概要 / 明细 / 操作记录」，
  返回时列表停留在原页码与原筛选。
- 理由：可直达（客服能发链接）、可刷新、Tab 状态可进 URL。

**示例二：启用状态**

- ❌ 一个 2 项下拉：`启用 / 停用`，选中后还要点「保存」。
- ✅ 一个开关，切换即提交，提交中置灰并显示进度，失败自动回到原状态并给出原因。

**示例三：日期筛选**

- ❌ 两个独立日期输入框 + 一个「近 7 天」按钮，点了按钮输入框不变。
- ✅ 日历内平铺快捷项（今天 / 近 7 天 / 本月 / 自定义），选择后范围回显在输入框，
  超出租期上限的日期置灰，跨时区时显示基准时区。

**示例四：10 项以上的组织选择**

- ❌ 平铺 30 个单选按钮。
- ✅ 搜索型选择器：外边框 + 已选回显 + 支持输入过滤；空结果明确提示「无匹配」。
